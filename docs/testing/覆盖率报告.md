### 未覆盖行说明

- `CountdownEvent.ets` 的 `milestoneProgress()` 中 `span <= 0` 属数学上不可达的防御分支
  （下一个里程碑的 `daysFromBase` 必然大于上一个），保留用于防御异常数据。
- 报表把该文件的 1~8 行记为未覆盖，是转译后 source map 的行号映射差异（数组常量在模块加载时即执行），
  实际已被用例执行。
- `PinLock.ets` 的 236~244 行是 `PinVerifyResult` 接口声明（无运行时代码）；`EventStore.ets` 第 171 行是迁移写入的防御性 `catch` 回调。
- `pages/Index.ets`、`widget/pages/WidgetCard.ets` 为声明式 UI DSL，无法在 Node 中渲染；
  其中的纯逻辑（筛选排序、统计、文案、日期步进、计算器）已抽离到 `EventQuery.ets` / `DateStepper.ets`
  并被完整覆盖，UI 部分仍以云真机回归为准。

## 四、测试运行原理

```
entry/src/test/*.test.ets  ──┐
                             ├─► tools/coverage/build.js（.ets → CommonJS + source map）
entry/src/main/ets/**/*.ets ─┘            │
                                          ▼
                         @kit.* 替换为 tools/coverage/stubs/*（内存桩）
                                          │
                                          ▼
                    tools/coverage/hypium.js（describe/it/expect 兼容层）
                                          │
                                          ▼
              node --test --experimental-test-coverage --enable-source-maps
```

- 桩模块用「魔法输入」触发失败分支（如事件名 `__fail__` 让卡片推送抛错），避免在用例里操作全局开关；
- source map 让覆盖率报告直接对应 `.ets` 行号，未覆盖行可直接跳转定位；
- 用例写在 `entry/src/test/` 下，与 DevEco 的 Local Test 目录一致，后续可在 IDE 内复用。

## 五、CI 接入

```bash
node tools/coverage/run.js --threshold=95
```

退出码：0 = 用例全绿且覆盖率达标；非 0 = 用例失败或覆盖率不达标。
